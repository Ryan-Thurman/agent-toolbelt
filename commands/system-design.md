# /system-design

Use `$system-design` for `$ARGUMENTS`.
Reuse the project's design record and preserve its requirements.
For architecture questions, investigate relevant evidence, compare viable approaches, and resolve consequential uncertainty through focused questions.
For decision records, preserve the actual approval state and links to earlier decisions.
For a current repository map, deliver source-backed modules, dependencies, entry-point flows, and coverage limits.
For a proposed design, deliver the design, linked threat review, security requirements, and unresolved decisions.
